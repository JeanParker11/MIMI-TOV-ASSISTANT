1. La Philosophie : L'ID est la Clé
 * Le Fichier data/competences.json : Contient la définition de chaque compétence (son nom, son type, et surtout, sa mécanique).

2. Le Langage du Bot : data/competences.json
Voici la structure que je te propose. C'est le "langage" que le bot peut interpréter.
Chaque compétence aura cette structure :
{
  "id": "SKILL_UNIQUE_ID",
  "nom": "Nom lisible par l'humain",
  "type": "passive" | "active",
  "description": "Ce que ça fait, pour la commande !fiche",
  "mecanique": {
    "declencheur": "...",
    "condition": { ... },
    "effet": { ... },
    "cout": { ... }
  }
}

 * id: L'identifiant unique (ex: "regen_mineure", "eclat_solaire_1").
 * type: active ou passive.
 * mecanique: C'est le cerveau de la compétence.
   * declencheur: (Pour les passifs) Quand le bot doit-il vérifier ce skill ?
   * condition: (Optionnel) Le déclencheur est-il soumis à une condition ?
   * effet: Qu'est-ce que la compétence fait ?
   * cout: (Pour les actifs) Qu'est-ce que ça coûte de l'utiliser ?

5. Algorithme (Comment le bot gère tout ça)
 * Au Démarrage du Bot : Le bot charge data/competences.json une seule fois dans sa mémoire (le "Compendium").
 * Au Début du Combat :
   * Le bot scanne tout l'équipement du Joueur 1 (arme, armure, runes...).
   * Il collecte tous les ID de compétences (ex: ["souffle_glace_1", "regen_pv_1", "fureur_du_blesse_1"]).
   * Il crée une liste des compétences actives et passives du joueur pour ce combat en allant chercher les définitions complètes dans le Compendium.
 * Pendant le Combat (lib/combatLogic.js) :
   * Début de tour ? Le bot parcourt la liste des passifs du joueur et exécute tous ceux dont le declencheur est "debut_tour_joueur".
   * Action !souffle_glace ? Le bot vérifie si "souffle_glace_1" est dans la liste des actifs du joueur, puis applique l'effet et le coût.
   * Le joueur prend des dégâts ? Le bot parcourt les passifs et vérifie les conditions (ex: "fureur_du_blesse_1").
C'est un système robuste qui centralise toute la logique de combat en un seul endroit.

2. L'Algorithme de Reconnaissance (dans combatManager.js)

PROCÉDURE traiterMessageDeCombat(messageUtilisateur)
DEBUT

    // On enlève le "!" (si vous l'utilisez) et on met tout en minuscule
    // "   !Souffle Glacé   " -> "souffle glacé"
    commande = nettoyerMessage(messageUtilisateur) 
    
    // 2. Vérifier si c'est une compétence active
    // Le bot consulte sa "Table de Correspondance"
    competenceID = trouverIDparNom(commande) 
    
    // 3. Si une correspondance est trouvée...

        // 4. Vérifier si le joueur POSSÈDE cette compétence

            // 5. Transmettre l'ID à la logique de combat

1. Dictionnaire de Réussite (Logique Interne du Bot)
D'abord, nous allons "coder en dur" ce tableau de chances de réussite dans lib/combatLogic.js. Ce sera la référence que le bot utilisera.
// Dans lib/combatLogic.js
const CHANCES_REUSSITE_PAR_RANG = {
    'E': 20,
    'D': 40,
    'C': 60,
    'B': 70,
    'A': 80,
    'S': 90
};

2. L'Algorithme du "Jet de Réussite" 🎲
Nous créons une nouvelle fonction utilitaire qui sera appelée chaque fois qu'une compétence tente de s'activer.
/* * Nouvelle fonction dans lib/combatLogic.js
 * Elle vérifie si une compétence réussit son activation.
 */
FONCTION verifierReussite(rangDeLaCompetence)
DEBUT
    
    // 1. Trouver le % de chance de base
    chanceDeBase = CHANCES_REUSSITE_PAR_RANG[rangDeLaCompetence]
    
    // Si la compétence n'a pas de rang défini (ex: attaque de base), on assume 100%
    SI chanceDeBase EST INDÉFINI ALORS
        RETOURNER VRAI (Succès automatique)
    FIN SI
    
    // 2. Lancer un dé de 100
    jetAleatoire = ALEATOIRE(1, 100)
    
    // 3. Comparer le jet au seuil de réussite
    SI jetAleatoire <= chanceDeBase ALORS
        RETOURNER VRAI (Succès 🎯)
    SINON
        RETOURNER FAUX (Échec ❌)
    FIN SI

FIN FONCTION

3. Intégration dans la Logique de Combat
C'est l'étape la plus importante. Nous devons insérer ce "jet de réussite" au bon moment.
Pour les Compétences Actives (ex: !boule_de_feu)
La règle d'or est : Le coût (mana, utilisation) est payé d'abord, puis le jet de réussite est lancé. C'est ce qui crée la tension. Si tu rates, tu perds quand même ta ressource.
PROCÉDURE executerCompetenceActive(joueur, competence)
DEBUT
    
    // 1. Vérifier les coûts (mana, cooldown, charges d'utilisation)
    SI le joueur NE PEUT PAS payer le coût ALORS
        RETOURNER "Vous n'avez pas les ressources nécessaires."
    FIN SI
    
    // 2. Payer le coût (!!!)
    consommerRessources(joueur, competence.mecanique.cout)
    
    // 3. NOUVELLE ÉTAPE : Lancer le dé de réussite
    reussite = verifierReussite(competence.rang)
    
    SI reussite == FAUX ALORS
        RETOURNER "Échec ! Votre compétence '" + competence.nom + "' rate..."
    FIN SI
    
    // 4. Si on arrive ici, c'est un succès. Appliquer l'effet.
    appliquerEffet(joueur, competence.mecanique.effet)
    RETOURNER "Succès ! '" + competence.nom + "' s'active !"

FIN PROCÉDURE

Pour les Compétences Passives (ex: Régénération)
C'est similaire. Quand le déclencheur est atteint (ex: "début de tour"), le bot fait le jet de réussite avant d'appliquer l'effet.
PROCÉDURE verifierPassifsAuDebutDuTour(joueur)
DEBUT
    POUR chaque competence DANS les passifs du joueur
    DEBUT
        // 1. Vérifier si c'est le bon déclencheur
        SI competence.mecanique.declencheur == "debut_tour_joueur" ALORS
            
            // 2. NOUVELLE ÉTAPE : Lancer le dé de réussite
            reussite = verifierReussite(competence.rang)
            
            SI reussite == VRAI ALORS
                // 3. Appliquer l'effet
                appliquerEffet(joueur, competence.mecanique.effet)
                AjouterAuLog(competence.nom + " s'active !")
            // SI FAUX, on ne fait rien (le passif ne s'active pas ce tour-ci)
            FIN SI
        FIN SI
    FIN POUR
FIN PROCÉDURE

Note Importante : L'Override (La Règle d'Exception)
Que faire si une compétence de Rang E doit réussir à 100% ? (Ex: un soin de base).
Nous pouvons ajouter un champ optionnel dans data/competences.json :
"mecanique": {
    "taux_reussite_override": 100, // Ce champ ignore le rang
    "declencheur": "..."
}

La fonction verifierReussite vérifiera d'abord si ce champ existe. Si oui, elle l'utilise. Sinon, elle utilise le rang.
